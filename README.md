# Kalyazin eye — «Ухо» (макет РТ-64)

wb-rules для Wiren Board (контроллер «Свет», `192.168.69.106`; на контроллере файл
лежит как `/etc/wb-rules/ear.js`, в репозитории — [rules/ear.js](rules/ear.js)).
Виртуальное устройство `ear` — наведение макета радиотелескопа по азимуту и элевации.

Техника (железо, настройки модулей, калибровка, гочи) — в [KNOWLEDGE.md](KNOWLEDGE.md).
Другие подсистемы того же контроллера — в [rules/](rules/README.md).

## Оси

- **Азимут:** 0…330°, увеличение = по часовой. `0°` = концевик IN1 (против-часовой конец),
  `330°` = IN2 (по-часовой упор). Home/парковка → 330°.
- **Элевация:** 35…90°. `35°` = IN3 (низ), `90°` = IN4 (верх). Парковка вверх (90°).

# Управление по MQTT

Брокер mosquitto — на самом контроллере, из локалки обращаемся по `192.168.69.106:1883`.

Соглашение Wiren Board:
- **текущее значение** читается из `/devices/ear/controls/<control>`;
- **команда** отдаётся публикацией в `/devices/ear/controls/<control>/on`.

## Топики

| Контрол | Тип | Чтение (значение) | Команда (`.../on`) | Что делает |
|---|---|---|---|---|
| `azimuth`   | range 0–330° | да (текущий азимут) | да (целевой) | записал число → едет в этот азимут |
| `elevation` | range 35–90° | да (текущая элевация) | да (целевая) | записал число → едет в эту элевацию |
| `home`      | pushbutton | — | да | хоминг + парковка: азимут → 330° (IN2), элевация → 90° (IN4) |
| `stop`      | pushbutton | — | да | **аварийный стоп** обеих осей (прерывает и сценарий) |
| `scenario`  | pushbutton | — | да | **запустить сценарий** (заранее записанную последовательность) |
| `sync`      | switch | да | да | согласованное ведение: обе оси приходят в цель **одновременно** (по умолчанию вкл) |
| `scenarioSteps` | text | да (текущий сценарий) | да, **только по MQTT** (в вебе только просмотр) | шаги сценария в JSON; сохраняется между перезагрузками |
| `homed`     | switch (0/1) | да | — | референс установлен (обе оси отхоминжены) |
| `status`    | text | да | — | `idle` / `homing` / `moving` / `parked` / `ERROR: …` |
| `azTicks`   | value | да | — | приращение тиков за текущее движение (отладка; сброс после стопа) |
| `elTicks`   | value | да | — | то же для элевации |

## Примеры

Указываем брокер контроллера `192.168.69.106` (порт 1883). На компе нужны утилиты
`mosquitto_pub` / `mosquitto_sub`:
- **Linux:** `apt install mosquitto-clients`.
- **Windows:** отдельного пакета клиентов нет — поставить Mosquitto для Windows
  (https://mosquitto.org/download/); `mosquitto_pub.exe` / `mosquitto_sub.exe` окажутся в папке
  установки (обычно `C:\Program Files\mosquitto\`). Сам брокер запускать не нужно — нужны только эти exe.

Если на брокере включены логин/пароль — добавляй `-u <user> -P <pass>`.

Прочитать текущий азимут (одно значение):
```sh
mosquitto_sub -h 192.168.69.106 -t '/devices/ear/controls/azimuth' -C 1
```

Ехать в азимут 120°:
```sh
mosquitto_pub -h 192.168.69.106 -t '/devices/ear/controls/azimuth/on' -m 120
```

Ехать в элевацию 60°:
```sh
mosquitto_pub -h 192.168.69.106 -t '/devices/ear/controls/elevation/on' -m 60
```

Хоминг / парковка (az→330, el→90):
```sh
mosquitto_pub -h 192.168.69.106 -t '/devices/ear/controls/home/on' -m 1
```

Аварийный стоп:
```sh
mosquitto_pub -h 192.168.69.106 -t '/devices/ear/controls/stop/on' -m 1
```

Следить за статусом и позициями в реальном времени:
```sh
mosquitto_sub -h 192.168.69.106 -v \
  -t '/devices/ear/controls/status' \
  -t '/devices/ear/controls/azimuth' \
  -t '/devices/ear/controls/elevation' \
  -t '/devices/ear/controls/homed'
```

## Сценарии

Одна кнопка **`Run scenario`** проигрывает заранее записанную последовательность. Каждый следующий
шаг стартует **после остановки** предыдущего — как и просили.

Шаги задаются JSON-массивом в контроле **`Scenario (JSON)`** (`scenarioSteps`), его можно
редактировать прямо в веб-интерфейсе или по MQTT; значение сохраняется между перезагрузками.

| Шаг | Смысл |
|---|---|
| `{"az":120}` | ехать в азимут 120° |
| `{"el":60}` | ехать в элевацию 60° |
| `{"az":120,"el":60}` | обе оси одновременно |
| `{"pause":5}` | пауза 5 секунд (после остановки) |
| `{"home":true}` | хоминг/парковка: az 330°, el 90° (в конце сценария не нужен — парковка автоматическая) |

**По завершении сценария антенна ВСЕГДА уходит в парковку** (az 330°, el 90°) — отдельный шаг
`{"home":true}` в конце списка не требуется.

Сценарий по умолчанию (обзор горизонта с проходами по высоте):

```json
[{"az":250,"el":60},{"pause":3},{"az":120},{"pause":2},{"el":45},{"az":40},{"pause":3},{"el":75},{"az":200},{"pause":2}]
```

Запустить и записать свой сценарий по MQTT:
```sh
mosquitto_pub -h 192.168.69.106 -t '/devices/ear/controls/scenario/on' -m 1
```
```sh
mosquitto_pub -h 192.168.69.106 -t '/devices/ear/controls/scenarioSteps/on' \
  -m '[{"az":90},{"pause":10},{"el":50},{"home":true}]'
```

Пока сценарий идёт, `status` показывает прогресс: `scenario 3/11: az 120`, `scenario 4/11: pause 2s`.
Особенности:
- **перед запуском нужен `Home`** (без референса позиции сценарий не стартует — статус `need home`);
- **`Stop` прерывает** сценарий в любой момент;
- **ошибка оси сценарий НЕ прерывает** — ось, которая встала, считается отработавшей, шаг закрывается, сценарий идёт дальше; текст ошибки виден в `status` в квадратных скобках, напр. `scenario 5/11: el 45 [el: motor not turning (stall)]`;
- во время сценария, включая паузы, автопарковка по простою не срабатывает;
- битый JSON не применяется — в `status` будет `ERROR: bad scenario JSON`.

## Согласованное ведение двух осей (`sync`)

Настоящий РТ‑64 — альт-азимутальный: обе оси работают одновременно, иначе объект не вести.
У макета это тоже поддержано — шаг вида `{"az":120,"el":60}` (или две команды подряд) запускает
обе оси, и при включённом `sync` **они приходят в цель одновременно**, а трасса в координатах
az/el получается прямой линией.

Как сделано: скорость у приводов фиксированная 2 % (ниже двигатель не страгивается), поэтому
«замедление» реализовано **придерживанием** — ось, ушедшая вперёд по доле пройденного пути более
чем на 3 %, кратковременно паузится, пока вторая догоняет (отпускается при расхождении < 1 %).
Ось с более длинным ходом идёт непрерывно, короткая — с микропаузами.

Выключить (`sync` = off) — оси едут независимо, каждая на своих 2 %, и приезжают когда приедут.

Отличие от настоящего телескопа: у нас согласован **приход в точку**, а не ведение по небесной
траектории с непрерывно меняющимся соотношением скоростей.

## Способы управления

1. **По MQTT** (см. выше) — из скриптов, с другого компа в локалке, из внешней автоматики.
2. **С веб-интерфейса контроллера** — дашборд **«Ear (RT-64)»** (стоит по умолчанию; демо-дашборды
   убраны). Виджеты: *Pointing* (Azimuth, Elevation, Home, Stop, Status, Homed) и *Scenario*
   (Run scenario, Sync axes, поле Scenario JSON — только просмотр). Также доступно на странице устройств: тянешь ползунок `Azimuth` / `Elevation` — антенна едет
   туда; в движении ползунок неактивен и показывает текущее положение; кнопки `Home` и `Stop`
   работают так же, как MQTT-команды. Это штатный ручной режим.
3. **Сервисный (ручной) режим — напрямую каналами WB-LED**, минуя `ear.js`. Нужен для наладки,
   проверки механики и вытаскивания оси из упора. Порядок:
   - сначала **`Stop`** у устройства `ear` (правило уходит в `idle` и перестаёт трогать каналы —
     иначе оно будет спорить с ручными командами);
   - затем крутить руками через устройство `wb-led_71`: направление — `Channel 2` (азимут) /
     `Channel 4` (элевация), скорость — включить `Channel 1` / `Channel 3` и задать
     `Channel N Brightness` (рабочее значение 2 %);
   - остановка — выключить канал скорости (`Channel 1` / `Channel 3` = off).

   В сервисном режиме **защита концевиками продолжает работать** — она зашита в сам модуль WB-LED
   (реверс при нажатии, стоп на сходе), контроллер для этого не нужен. Подробности — в
   [KNOWLEDGE.md](KNOWLEDGE.md).
   После ручных манипуляций позиция в `ear` может «уехать» — сделать `Home`, чтобы вернуть референс.

## Нюансы

- **Кнопки `home`/`stop` — pushbutton:** публикуй любое значение, например `-m 1` (срабатывает каждый раз).
- **Во время движения ползунок readonly, новые цели по нему игнорируются** (защита от эха собственных обновлений «текущего»). Чтобы перенацелить на ходу — сначала `stop`, затем новая цель. Либо дождаться остановки.
- **Позиция достоверна только после `home`** (`homed`=1). До хоминга текущее положение неизвестно.
- **Скорость всегда 2 %** (задано в правиле).
- Приезд на концевик и откат с него отрабатывает сам модуль WB-LED; правило не оставляет концевик нажатым.
- **Срабатывание ЛЮБОГО концевика обновляет позицию** этой оси (снап в 0° / конец диапазона) и ставит `homed`. Во время хоминга встречный концевик позицию тоже обновляет, но сам хоминг не завершает.
- **Хоминг завершается двумя путями:** по достижению целевого концевика (раньше, точно, с авто-откатом модуля) ЛИБО по истечении времени (`homeTimeMs`: азимут ~65 с, элевация ~20 с) — тогда позиция считается доехавшей до референса. После завершения Home (в т.ч. с ошибкой) счётчики MCM8 сбрасываются.
- Двигать ползунком можно только после `home` (пока не отхоминжено — команда игнорируется со статусом `need home`).
