# pump-level — управление насосом по уровню воды

Держит уровень воды у заданной уставки, включая и выключая насос по гистерезису.
Уровень измеряется датчиком с токовым выходом (4–20 мА) через аналоговый вход
Wiren Board, а ток переводится в миллиметры по калибровочной таблице.

В папке два куска одной темы:

| Что | Где |
|-----|-----|
| Само правило `wb-rules` | [`water_level.js`](water_level.js) — описано ниже |
| Сенсорный пульт на Android-панели | [`hmi-panel/`](hmi-panel/) — свой README |

## Как считается уровень

Датчик установлен **перевёрнуто**: чем больше воды — тем **меньше** ток.
Поэтому уровень считается по инвертированной модели:

```
level_mm = OFFSET − interp(ток) + «Изменить уровень»
```

- `interp(ток)` — кусочно-линейная интерполяция по калибровочной таблице
  `CAL` (ток датчика, мА → собственная шкала датчика, мм). За границами таблицы
  значение фиксируется на крайней точке (clamp).
- `OFFSET = 76.86` — смещение установки датчика. Получено из полевого замера:
  реальные **68 мм** при токе **12.53 мА** → `OFFSET = 68 + interp(12.53)`.
- `«Изменить уровень»` — ручная коррекция показания, ±5 мм.

Уставка всегда фиксирована — **70 мм** (`SETPOINT`), триммер правит показание, а не цель.

### Калибровочная таблица

Датчик **нелинейный**, аналитической формулы для него нет — поэтому в правиле
лежит снятая руками таблица `CAL`: **49 точек** вида `[ток, мм]`, ток строго
возрастает от **0.69 до 19.72 мА**, собственная шкала датчика — от **0 до
26.02 мм**. Между точками — линейная интерполяция, за границами таблицы значение
фиксируется на крайней точке (clamp), то есть обрыв или закоротка дадут не
абсурд, а край диапазона.

Нелинейность видна прямо по шагу таблицы. В рабочей середине один миллиметр
шкалы стоит примерно 1.5 мА:

```
 4.06 мА → 3.90 мм        ~1.4 мА на мм
11.27 мА → 8.10 мм        ~1.6 мА на мм
16.37 мА → 12.00 мм       ~1.2 мА на мм
```

а к верху кривая складывается, и те же десятые доли миллиметра стоят уже
сотые доли миллиампера:

```
19.58 мА → 23.51 мм
19.62 мА → 24.15 мм       0.04 мА на 0.64 мм
19.72 мА → 26.02 мм
```

Последние 3 мм шкалы уложились в 0.14 мА — это и есть насыщение. Читать уровень
в этой зоне бессмысленно: шум токового входа превращается в сантиметры.

### Про насыщение и рабочую точку

- При токе выше ~17 мА разрешение по уровню резко падает (см. выше). Рабочая
  точка (~11–12.5 мА) лежит в приличной части кривой — это хорошо.
- Два полевых замера (70 мм @ 11 мА и 68 мм @ 12.53 мА) в инвертированной модели
  сходятся с точностью ~1 мм. Остаточный ~1 мм — это наклон кривой, не смещение;
  если понадобится точнее, надо пересобрать таблицу `CAL` по нескольким точкам.

## Контролы (виртуальное устройство `pump_ctrl`)

| Контрол | Тип | Назначение |
|---------|-----|------------|
| Авторежим | switch | Включает автоматическое управление насосом |
| Уровень воды | value, мм | Текущий вычисленный уровень (readonly) |
| Насос работает | switch | Состояние насоса (readonly, синхронизируется с Innovert) |
| Изменить уровень | range, −5…+5 мм, шаг 0.1 | Ручная коррекция показания |
| Гистерезис | value, мм | Ширина зоны нечувствительности (по умолчанию 1.5 мм) |

Гистерезис задаётся как **полная ширина коридора**: пороги = `70 ± Гистерезис/2`.
При 1.5 мм: насос ВКЛ при `level ≤ 69.25`, ВЫКЛ при `level ≥ 70.75`.

## Как управлять насосом без пульта

Панель у насосной — не единственный способ. То же самое делается из штатного
веб-интерфейса контроллера, с любого компьютера или телефона в сети объекта.

**1. Зайти в веб-интерфейс.** Открыть `http://192.168.69.101/` и войти —
с 14.08.2026 требуется учётная запись (`admin`, `operator` или `user`).
Дальше раздел «Устройства».

**2. Автоматический режим.** Устройство **Pump Level Control** (`pump_ctrl`):

| Контрол | Что делать |
|---------|------------|
| Авторежим | включить — дальше насос держит уровень сам |
| Уровень воды | смотреть текущий уровень, мм |
| Насос работает | смотреть, крутится ли насос |

Этого достаточно в обычной работе: уровень держится у 70 мм, включения и
выключения происходят сами. Каждый вечер в 20:00 авторежим снимается по
расписанию — утром его включают заново.

**3. Ручной пуск.** Сначала **выключить Авторежим** — иначе правило вернёт своё
через пару секунд, и ручная команда просто не удержится.

Затем устройство **`INNOVERT-ISD-mini-PLUS_101`** (частотник), контрол
**«Команда управления»**:

| Значение | Что происходит |
|----------|----------------|
| `2` | пуск |
| `1` | стоп |

Убедиться, что насос действительно пошёл, надо не по команде, а по факту:
**«Выходная частота»** должна стать ненулевой (рабочая ~33 Гц), **«Выходной
ток»** — порядка 13 А. Команда показывает лишь то, что мы попросили.

> **Ручной пуск ничем не ограничен по времени.** Восьмиминутная защита
> `MAX_RUN_SEC` работает только для пусков от автоматики, а автостоп через
> 15 минут есть лишь на сенсорном пульте. Пустив насос отсюда, его надо
> **остановить руками** и следить за уровнем, чтобы не перелить.

**4. То же самое из консоли**, если веб-интерфейс недоступен или удобнее
по SSH:

```bash
ssh -i ~/.ssh/id_ed25519_wb root@192.168.69.101

# снять авторежим
mosquitto_pub -t '/devices/pump_ctrl/controls/auto_mode/on' -m 0

# пуск и стоп
mosquitto_pub -t '/devices/INNOVERT-ISD-mini-PLUS_101/controls/Команда управления/on' -m 2
mosquitto_pub -t '/devices/INNOVERT-ISD-mini-PLUS_101/controls/Команда управления/on' -m 1

# что происходит прямо сейчас
mosquitto_sub -t '/devices/pump_ctrl/controls/+' -v
mosquitto_sub -t '/devices/INNOVERT-ISD-mini-PLUS_101/controls/Выходная частота' -v
```

Запись всегда идёт в топик с суффиксом `/on`, чтение — из топика без него. Если
писать в топик состояния напрямую, значение вернётся обратно при первом же
опросе устройства.

## Защиты

- **Максимальное время работы** (`MAX_RUN_SEC = 8 мин`) — аварийное отключение,
  если насос не останавливается.
- **Пауза после остановки** (`MIN_OFF_PAUSE_SEC = 30 с`) — блокировка повторного
  пуска, чтобы не дёргать насос.
- **Автовыключение в 20:00** — авторежим снимается по расписанию (cron, UTC+3).
- При переходе насоса в «стоп» (в т.ч. вручную) статус и таймеры синхронизируются.

## Развёртывание

```bash
scp water_level.js root@192.168.69.101:/etc/wb-rules/
ssh root@192.168.69.101 journalctl -u wb-rules --since '30s ago' --no-pager
```

**Имя файла менять нельзя.** `wb-rules` подхватывает всё из `/etc/wb-rules/`, и
копия под другим именем не заменит правило, а добавит второе с той же логикой —
насосом начнут управлять два правила сразу. Поэтому в репозитории файл назван
ровно так же, как на контроллере: `water_level.js`.

Сохранение файла заставляет `wb-rules` перечитать правило на живую. Виртуальное
устройство при этом переопределяется, но значения контролов сохраняются
(проверено 10.08.2026: `auto_mode`, `level_trim`, `hyst_mm` остались прежними).
Синтаксические ошибки наружу не всплывают — журнал смотреть обязательно.

Содержимое здесь и на контроллере сверено 10.08.2026 — совпадает.

## Что проверить на месте / TODO

- **Ползунок «Изменить уровень»:** у типа `range` в некоторых версиях homeui не
  отрабатывает `min` (ползунок начинается с 0). Убедиться, что реально ходит в −5
  и шаг 0.1. Если нет — переделать на `range 0…100` с пересчётом в коде.
- **Сухой ход:** при осушении ток растёт к насыщению, `level_mm` падает (~50.8 мм
  на самом низу) → насос корректно включается. Но по одному `level_mm` «сухой ход»
  не отличить от низкого уровня. При желании — добавить аларм по току
  (ток > ~19 мА дольше N секунд → авария + запрет пуска).
- **Наклон кривой:** если реальный уровень и `level_mm` расходятся тем сильнее,
  чем дальше от 68 мм — пересобрать таблицу `CAL` по нескольким точкам.
