# hmi-panel — сенсорный пульт насосной

Одностраничный пульт для Android-панели, висящей рядом с насосной макета
«Живая вода». Показывает уровень воды, состояние насоса и реле, позволяет
переключать режим и вручную пускать насос.

Весь пульт — **один файл [`index.html`](index.html) без единой библиотеки**. Это
сознательно: панель работает в замкнутой сети без интернета, а обновление
сводится к копированию одного файла.

Автоматика уровня живёт в правиле рядом — [`../water_level.js`](../water_level.js),
описание в [README темы](../README.md). Пульт её только отображает и
переключает, своей логики поддержания уровня в нём нет.

## Железо

| Что | Где |
|-----|-----|
| Контроллер | Wiren Board 7.4.2, `192.168.69.101` |
| Панель | Android 13, RK3566 (`YC-SM08P`), 1280×800 ландшафт, 180 dpi, `192.168.69.227` |
| Браузер | Fully Kiosk 1.60.1, **бесплатная версия** |
| Датчик уровня | 4–20 мА на `wb-mai2-mini_171`, канал 1 |
| Насос | частотник `INNOVERT-ISD-mini-PLUS_101` |
| Реле | цепочка 101 → 102 → 103 → 105 → 106, 30 каналов |
| Токи | `wb-map12e_104`, 12 входов |

180 dpi значит, что 10 мм на экране — это 71 px; отсюда `--strip: 71px` в стилях
(ширина «корешка» соседней страницы).

# Как положить страницу на контроллер

Страница отдаётся штатным nginx контроллера из `/var/www`, никакой настройки
веб-сервера не требуется — просто положить файл в подпапку:

```bash
scp pump-level/hmi-panel/index.html root@192.168.69.101:/var/www/kiosk/index.html
```

**Страница физически лежит на разделе данных** — `/mnt/data/www/kiosk/` — и
переживает перезапись корневой файловой системы (перепрошивку, смену релиза).
Владелец каталога `www-data:www-data`, как у штатного `uploads`.

Ведут туда два независимых пути, оба через штатные механизмы WB:

1. **Правило nginx** `/etc/nginx/includes/default.wb.d/kiosk.conf` — nginx читает
   раздел данных напрямую, без посредников:

   ```nginx
   location /kiosk/ {
       alias /mnt/data/www/kiosk/;
       index index.html;
   }
   ```

   `default.wb.d/*.conf` — это штатное место для своей конфигурации, так написано
   в шапке самого `sites-available/default`.

2. **Симлинк** `/var/www/kiosk -> /mnt/data/www/kiosk` — запасной путь, работает
   если файл правила потеряется. Сделан по образцу WB, который так же уводит
   `/var/www/uploads` на `/mnt/data/uploads`.

Оба живут на корневой ФС, поэтому после её перезаписи восстанавливается что-то
одно — сама страница при этом никуда не девается:

```bash
ln -s /mnt/data/www/kiosk /var/www/kiosk
```

Адрес при всём этом один и тот же — `http://192.168.69.101/kiosk/`. Панель ничего
не знает про пути в файловой системе и настройки не требует.

Проверить, что отдаётся: `http://192.168.69.101/kiosk/`

Если с вашей машины контроллер напрямую не виден, он за Tailscale-мостом:

```bash
scp -o ProxyJump=root@100.98.33.26 pump-level/hmi-panel/index.html \
    root@192.168.69.101:/var/www/kiosk/index.html
```

**Страница не перечитается сама.** Она загружается один раз и живёт в браузере
панели неделями. После замены файла надо перезапустить Fully — см. ниже
«Управление панелью». Обновление вкладки внутри Fully по опыту не помогает:
адрес тот же, и браузер отдаёт своё.

# Настройка панели

## Что уже настроено

Значения сняты с работающей панели (`de.ozerov.fully_preferences.xml`):

| Настройка Fully | Значение | Зачем |
|-----------------|----------|-------|
| Start URL | `http://192.168.69.101/kiosk/` | что открывать при старте |
| Launch on Boot | `true` | подняться самому после перезагрузки панели |
| Keep Screen On | `true` | экран не гаснет |
| Show Action Bar | `false` | убрать верхнюю панель Fully |
| Show Address Bar | `false` | убрать строку адреса |
| Show Progress Bar | `false` | убрать полосу загрузки |
| Force Screen Orientation | `0` (как есть) | панель и так стоит ландшафтом |

Три `false` в конце — это ровно то, из-за чего картинка сначала была не на весь
экран. Без них сверху остаются полосы Fully.

## Чего в бесплатной версии нет

- **Kiosk Mode** и любые PIN на выход — платные (PLUS). Поэтому выход
  блокируется не Fully, а штатным Android screen pinning (ниже).
- **Website Integration** (`websiteIntegration = false`) — это JS-интерфейс
  Fully, объект `fully` в странице. В бесплатной версии его нет, поэтому
  `typeof fully === 'undefined'`, и всё, что через него делается (снимок с
  камеры, управление яркостью, перезагрузка), недоступно.
- Все камерные настройки — тоже PLUS.

## Блокировка выхода

Штатным механизмом Android — screen pinning. Узнать `taskId` и закрепить:

```bash
adb shell dumpsys activity | grep -A2 "de.ozerov.fully/.FullyActivity"
adb shell am task lock <taskId>
```

В закреплённом состоянии `dumpsys activity | grep mLockTaskModeState` даёт
`PINNED`, кнопки HOME / BACK / RECENTS и шторка не работают. Снять:

```bash
adb shell am task lock stop
```

**Пиннинг не переживает перезагрузку панели** и сбрасывается при
`am force-stop` — то есть после каждого обновления страницы его надо ставить
заново. Автоматизации для этого пока нет.

## Часовой пояс — грабля

У панели `persist.sys.timezone = GMT`, а часы при этом показывают московское
время. Подписи графиков и счётчик «до автоотключения» считаются по времени
**панели**, а правило `auto_off_at_20` в контроллере — по своему. Сейчас они
совпадают, но если панель переставит часы, счётчик начнёт врать. При настройке
новой панели пояс лучше выставить явно.

# Управление панелью

ADB висит на порту 5555 **без авторизации** — так у неё из коробки, закрывать
не просили.

С обычной машины, где есть `adb`:

```bash
adb connect 192.168.69.227:5555
adb -s 192.168.69.227:5555 shell am force-stop de.ozerov.fully
adb -s 192.168.69.227:5555 shell am start -n de.ozerov.fully/.FullyActivity
```

На самом контроллере `adb` **нет**, и ставить его некуда. Для работы с панели
изнутри сети есть минимальный клиент [`adbmini.py`](adbmini.py) — рукописный
ADB на сокете, умеет ровно одно: выполнить shell-команду и вернуть вывод.

```bash
scp pump-level/hmi-panel/adbmini.py root@192.168.69.101:/tmp/
ssh root@192.168.69.101 'python3 /tmp/adbmini.py 192.168.69.227 "am force-stop de.ozerov.fully"'
```

Полезные команды через него:

```bash
A="python3 /tmp/adbmini.py 192.168.69.227"

# перезапустить пульт после замены страницы
$A "am force-stop de.ozerov.fully"; sleep 2
$A "am start -n de.ozerov.fully/.FullyActivity"

# что сейчас на экране
$A "dumpsys window | grep mCurrentFocus"

# скриншот (PNG в base64, декодировать у себя)
$A "screencap -p | base64"

# ткнуть в точку (например, в корешок «РЕЛЕ» справа)
$A "input tap 1240 383"
```

# Как устроено

- **Данные** — MQTT 3.1.1, реализованный руками поверх WebSocket на `/mqtt`
  (nginx контроллера проксирует на mosquitto). Авторизации у брокера нет.
- **История для графиков** — MQTT-RPC к `wb-mqtt-db`, топик
  `/rpc/v1/db_logger/history/get_values/<клиент>`, ответ на `.../reply`.
- **Навигация** — три страницы в горизонтальной ленте: «Насосная», «Реле»,
  «Настройки». У соседней страницы торчит корешок шириной 10 мм; тап по нему
  или свайп листает.

## Что правится в файле

Всё, что зависит от объекта, вынесено в начало скрипта:

| Переменная | Что задаёт |
|------------|------------|
| `TANKS` | ёмкости: топики уровня, датчика, уставка |
| `PUMPS` | насосы: устройство частотника и имена регистров |
| `RELAY_CHAIN` | порядок модулей реле в цепочке |
| `GROUPS` | разбивка 30 каналов на группы и подписи |
| `MODE_CTRL` | топик переключателя авто/ручного режима |
| `AUTO_OFF_HOUR` | час автоснятия авторежима (для счётчика на экране) |
| `SETTINGS_PIN` | код доступа к изменению настроек |
| `SETTINGS_IDLE_MS` | автовыход со страницы настроек |
| `MANUAL_RUN_MS` | автостоп насоса при ручном пуске |

Топики пишутся полностью, вместе с `/controls/`: `pump_ctrl/controls/level_mm`.
Однажды на этом уже спотыкались — без `/controls/` страница молча показывает
прочерки во всех полях.

## Разметка реле

Порядок каналов задан заказчиком: `101·K1 … 103·K3` — питание макета (15),
`103·K4` и далее 12 подряд — электроклапаны, остаток — резерв (3).

Клапаны подписаны по трём гидроузлам:

| Каналы | Узел | Клапаны |
|--------|------|---------|
| `103·K4…K6` | Дубна | наполнение русла, залив шлюза, слив шлюза |
| `105·K1…K3` | Углич | наполнение русла, залив шлюза, слив шлюза |
| `105·K4…K6`, `106·K1…K2` | Рыбинск | наполнение русла, залив 1, залив 2, слив 1, слив 2 |
| `106·K3` | — | подключён, назначения нет, подписан «Клапан» |
| `106·K4…K6` | — | резерв, запас на Рыбинск, не подключено |

У Рыбинска пять клапанов, потому что шлюз там парный.

**Клапаны и резерв без надобности не включать.**

Токи с MAP снимаются с реле питания блоков питания, а не с клапанов. Порядок
каналов внутри группы питания пока предположительный — подтвердить на объекте.

## Журнал действий

Страница публикует события в `/hmi/audit`, служба `hmi-audit.service` пишет их
в `/var/log/hmi-audit.log`. Логируются: разблокировка настроек (удачная и нет),
изменение параметров (что, с чего на что), переключение режима, пуск и останов
насоса. По журналу видно, сделано действие с пульта или откуда-то ещё — так,
например, выяснилось, что авторежим включают с дашборда через облако, а не с
панели.

# Ограничения, о которых стоит помнить

- **Код доступа лежит открытым текстом в странице.** Это защита от случайного
  тыка, а не настоящая: брокер без авторизации, писать в MQTT может кто угодно
  в сети.
- **Таймер ручного пуска живёт только в браузере.** Если панель перезагрузится
  с работающим насосом, автостоп через 15 минут не сработает. Штатная защита
  `MAX_RUN_SEC` в правиле ручной пуск не покрывает — это долг, закрывается при
  следующей переработке правил.
- **Графики — заглушка.** К ним отдельные требования, настраиваются позже.
- **Фото при вводе кода невозможно** на бесплатном Fully: `fully.getCamshot`
  есть только в PLUS, а `getUserMedia` не отдаёт камеру даже под HTTPS и с
  выданными правами (`NotAllowedError`). Проверено, откачено.
- **Пиннинг слетает** после перезагрузки панели и после `am force-stop`.
