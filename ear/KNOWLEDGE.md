# База знаний — «Ухо» (макет РТ-64)

Инженерная специфика проекта: железо, настройки модулей, автономная логика WB-LED, калибровка
и — главное — гочи и уроки, добытые отладкой. Управление по MQTT и назначение контролов — в
[README.md](README.md).

## Что это

Действующий макет радиотелескопа РТ-64 с моторизованным наведением по двум осям:
азимут (горизонт) и элевация (вертикаль). Классический альт-азимутальный монтаж.

## Железо

- **Приводы:** 2× BLDC-двигатель с редуктором и **встроенным драйвером**, **sensorless**, по одному на ось.
  Интерфейс управления стандартный:
  - вход скорости — ШИМ (0–100 %);
  - вход направления — дискретный (вкл/выкл);
  - выход импульсов скорости — обратная связь (заводим в WB-MCM8).
- **Модуль управления: WB-LED** (Modbus slave 71) — ШИМ-скорость и направление обеих осей.
- **Обратная связь: WB-MCM8** (Modbus slave 46), счётчики импульсов скорости:
  - азимут → `Input 3 counter`, элевация → `Input 2 counter`.
  - Sensorless-нюанс: импульс без знака (направление знаем только по своей команде →
    позиция dead-reckoning); на стопе сигнала нет; на очень малой скорости старт «дёргается».
- **Шина:** оба модуля на EBYTE-шлюзе **192.168.69.35:8886** (Modbus RTU-over-TCP, общий 9600-линк).
- **Контроллер:** «Свет» (`wirenboard-AIMOZTVW`, `192.168.69.106`) — общий, на нём и другие
  автоматизации (напр. KNX).

## Настройки модуля WB-LED (slave 71)

Заведён в `wb-mqtt-serial` на TCP-порту EBYTE `192.168.69.35:8886` (RTU-over-TCP), `device_type: WB-LED`.

Каналы (`dimmer_mode: 0` — 4 независимых W-канала):

| Канал | Назначение | MQTT-контрол |
|---|---|---|
| W1 (Channel 1) | ШИМ-скорость **азимута** | `wb-led_71/Channel 1` (вкл/выкл) + `.../Channel 1 Brightness` (0–100 % = ШИМ) |
| W2 (Channel 2) | **направление азимута** (вкл/выкл) | `wb-led_71/Channel 2` |
| W3 (Channel 3) | ШИМ-скорость **элевации** | `wb-led_71/Channel 3` + `.../Channel 3 Brightness` |
| W4 (Channel 4) | **направление элевации** (вкл/выкл) | `wb-led_71/Channel 4` |

Направление задаётся вкл/выкл канала (яркость каналов направления держим 100 %). Соответствие:
`Ch2=1` = против часовой (CCW), `Ch2=0` = по часовой (CW); `Ch4=0` = вверх, `Ch4=1` = вниз.
Рабочая скорость в правиле — всегда 2 %.

Частота ШИМ: `freq_div: 3` (делитель, holding-регистр 9).

Плавный пуск/торможение (фейдеры), значения — время перехода в условных единицах регистра
(0 = мгновенно, дефолт 1000, макс 30000; регистры inc 3000–3003, dec 3100–3103):

| Канал | inc (разгон) | dec (торможение) |
|---|---|---|
| W1 — скорость азимута | **2000** | 1000 (дефолт) |
| W3 — скорость элевации | **2000** | 1000 (дефолт) |
| W2 — направление азимута | 0 (мгновенно) | 0 |
| W4 — направление элевации | 0 (мгновенно) | 0 |

Входы IN1..IN4 — концевики, `input_X_mode: 1` (Switch, уровень).

Полный набор параметров (как в `wb-mqtt-serial.conf`):
```
dimmer_mode=0  freq_div=3
fader_inc_w1=2000  fader_inc_w3=2000  fader_inc_w2=0  fader_inc_w4=0
fader_dec_w2=0  fader_dec_w4=0        (dec для w1/w3 — дефолт 1000)
input_1_mode=1 input_2_mode=1 input_3_mode=1 input_4_mode=1
in1_switch_on_action=0  in1_switch_on_name=2  in1_switch_off_name=1
in2_switch_on_name_non_all=2                  in2_switch_off_name=1
in3_switch_on_action=0  in3_switch_on_name=4  in3_switch_off_name=3
in4_switch_on_name_non_all=4                  in4_switch_off_name=3
```

## Автономная логика WB-LED — откаты на концевиках

Вся отработка концевиков зашита в САМ модуль WB-LED (не в wb-rules). В режиме `Switch` у каждого
входа два действия над указанным каналом: при **срабатывании** (нажат) и при **отпускании** (сход).
Действие = Turn Off / Turn On / Toggle (по умолчанию on = Turn On, off = Turn Off).

Расшифровка настроенного (каналы: 1/3 = скорость аз/эл, 2/4 = направление аз/эл):

| Вход | Концевик | При СРАБАТЫВАНИИ | При ОТПУСКАНИИ (сход) |
|---|---|---|---|
| **IN1** | азимут, конец **0°** (CCW-упор) | канал **2** (напр. аз) → **Turn Off** (= CW, прочь от 0°) | канал **1** (скорость аз) → Turn Off (**стоп**) |
| **IN2** | азимут, конец **330°** (CW-упор) | канал **2** → **Turn On** (= CCW, прочь от 330°) | канал **1** → Turn Off (**стоп**) |
| **IN3** | элевация, **низ 35°** | канал **4** (напр. эл) → **Turn Off** (= вверх, прочь от низа) | канал **3** (скорость эл) → Turn Off (**стоп**) |
| **IN4** | элевация, **верх 90°** | канал **4** → **Turn On** (= вниз, прочь от верха) | канал **3** → Turn Off (**стоп**) |

**Как это работает (откат):**
1. Голова доезжает до концевика → вход СРАБАТЫВАЕТ → модуль переключает канал направления так,
   чтобы мотор пошёл ПРОЧЬ от этого концевика (реверс). Скорость при этом НЕ трогается.
2. Мотор (под питанием, в реверсе) сходит с концевика → вход ОТПУСКАЕТСЯ → модуль ВЫКЛЮЧАЕТ
   канал скорости → мотор **останавливается** чуть в стороне от концевика.

Итог: концевик никогда не остаётся вдавленным, голова паркуется у края, но не в упоре — **и всё это
без участия контроллера**.

**Важное следствие для wb-rules:** чтобы модуль успел откатить, скорость на концевике **нельзя гасить** —
её снимет сам модуль на сходе. Правило `ear.js` при достижении концевика уходит в ожидание
(`postlimit`) и не трогает канал скорости, отдавая откат модулю.

## Система координат и калибровка

- **Азимут:** 0…330°, **увеличение = по часовой**. `0°` = концевик **IN1** (против-часовой конец),
  `330°` = **IN2** (по-часовой упор). Полный ход ≈ **6868 тик** ≈ **20.8 тик/°**.
- **Элевация:** 35…90° (диапазон 55°). `35°` = **IN3** (низ), `90°` = **IN4** (верх).
  Полный ход ≈ **1242 тик** ≈ **22.6 тик/°**.
- Тик/сек (азимут): ~125 @2 %, ~180 @3 %, ~360 @10 %.
- Повторяемость полного хода: азимут разброс ~115 тик (~1.7 %), элевация ~28 тик (~2.3 %).
  Концевики как абсолютный референс стабильны; накопленную ошибку обнулять заездом (хомингом).
- Голова элевации **проседает под весом** (редуктор обратимый) — поэтому парковать вверх.

## Сброс счётчиков WB-MCM8

- Значения `Input N counter` — read-only input-регистры (записью 0 НЕ сбросить).
- Сброс всех счётчиков: контрол **`Reset all counters`** (holding-регистр 100, pushbutton):
  `mosquitto_pub -t /devices/wb-mcm8_46/controls/Reset\ all\ counters/on -m 1`.
- `ear.js` дёргает его автоматически после каждого Home (в т.ч. с ошибкой).

## Гочи и уроки (добыто отладкой)

1. **Концевик ловить по инкременту счётчика нажатий** `wb-led_71/Input N Counter` (заглавная `C`),
   а НЕ по уровню входа. При нажатии модуль мгновенно разворачивает мотор, и уровень при опросе
   раз в ~0.25 с легко промахнуться. (У счётчиков MCM8 — `Input N counter`, строчная `c`.)
2. **Откат с концевика делает сам модуль WB-LED, и это надо ему отдать.** На СХОДЕ с концевика
   модуль выключает канал скорости. Поэтому: уехать ОТ концевика можно только **переподтверждая
   скорость**; приезд НА концевик — **не гасить скорость**, модуль сам развернёт и остановит на сходе
   (голова встанет чуть в стороне, концевик не остаётся нажатым).
3. **Не переподтверждать привод каждый цикл** — WB-LED и MCM8 на одном 9600-линке; частые записи
   забивают шину, чтения счётчика «замирают» → ложный «нет тиков» → ложные срабатывания.
   Переподтверждать только когда модуль сам снял скорость или сменилось нужное направление.
4. **На 2 % цель проскакивается** (шаг за цикл > зоны). Перелетели — **стоп, назад не дёргать**
   (иначе рыскание). Зона нечувствительности ~1.8°.
5. **Парковка:** голову оставлять ВВЕРХУ, но **не вдавленной в концевик** (иначе тянется ремень).
   Достигается тем же авто-откатом модуля.
6. **Хоминг завершается по концевику ИЛИ по времени** (fallback). Реальный «мотор не крутится»
   ловится как ошибка только на `seek` (движении к цели), не на хоминге.
7. **MQTT-кнопки (pushbutton):** `-m 1` срабатывает каждый раз (не нужен уникальный аргумент).

## Софт

- `ear.js` — правило wb-rules, лежит в `/etc/wb-rules/` на контроллере.
- На контроллере **нет `wb-cli`** — деплой файлом (`scp`/`cat >`), движок сам перечитывает.
  Ошибки правила видны только в `journalctl -u wb-rules` (после каждого сохранения — смотреть лог).
- Язык wb-rules — ES5 (Duktape): без `let/const`, стрелок, шаблонных строк.
- Управление по MQTT — [README.md](README.md).

## Доступ и безопасность контроллера

Контроллер «Свет» приведён к той же схеме, что и «Boats» (09.08.2026):

- **Прошивка:** Debian 13 (trixie), релиз-target `wb8/trixie`, homeui 2.245.3.
  Переход делается штатно: `wb-release --update-debian-release` (контроллер должен быть на
  переходном релизе `wb-2606-trixie-transition`). Гоча: на полпути падает файловый конфликт
  `libcurl4-gnutls` ↔ старый `libcurl3-gnutls` — лечится `dpkg -i --force-overwrite`, затем
  `dpkg --configure -a` и повторным запуском `wb-release`. Обычный `apt install -f` в этот момент
  предлагает снести `wb-essential`/`wb-configs` — соглашаться нельзя.
- **Веб-интерфейс: три роли** (база `/mnt/data/var/lib/wb-homeui/users.db`):
  `admin`, `operator`, `user` — у `user` включён **автологин**, поэтому аноним видит дашборд и
  может управлять вынесенными на него контролами, а админские ручки (`/auth/users`) отдают 401.
  Пока в базе нет ни одного пользователя, подсистема авторизации не активна и веб полностью открыт;
  первого администратора заводят через мастер в вебе.
- **SSH:** вход по ключам (`/root/.ssh/authorized_keys`), root-пароль изменён с дефолтного.
- **MQTT:** на сетевом листенере 1883 — белый список (`acl_file`), наружу открыты только топики
  проекта:

  ```
  # /etc/mosquitto/acl/ear.conf
  topic readwrite /devices/ear/#
  ```

  Всё прочее (`system`, `wb-led_71`, `wb-mcm8_46`, KNX…) анонимному клиенту недоступно —
  и на чтение, и на запись; отказ по ACL брокер клиенту не сообщает, публикация просто теряется.
  **Важно:** под ACL попадает и обращение с самого контроллера по `127.0.0.1:1883`. Локальные
  службы (wb-rules и др.) не затронуты — они ходят через unix-сокет. Для диагностики на борту:

  ```sh
  mosquitto_sub --unix /var/run/mosquitto/mosquitto.sock -t '/devices/wb-led_71/controls/Channel 1' -C 1
  ```
