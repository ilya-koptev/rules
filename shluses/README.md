# shluses

Правило `wb-rules` для судоходного шлюза: двое ворот, камера, налив и слив.
Один и тот же файл на всех шлюзах — адреса модулей везде одинаковые.

Главное правило: **обе ворота никогда не открыты одновременно**, налив и слив — только
при закрытых обоих воротах.

## Модули

Все на `/dev/ttyRS485-2`, 115200 8N2. Адреса одинаковые на всех шлюзах:

| Адрес | Модуль | Что делает |
|---|---|---|
| 10 | WB-UPS v3 | резерв питания |
| 11 | WB-MAO4 | верхние ворота |
| 12 | WB-MAO4 | нижние ворота |
| 13 | WB-MCM8 | импульсы моторов: вход 1 — верхние, вход 2 — нижние |
| 14 | WB-MAI6 | IN1/IN2 — токи моторов (может не быть), IN5 — датчик уровня 4–20 мА |
| 15 | WB-MRM2-mini | K1 — налив камеры, K2 — слив |

### Как работают ворота

У каждого MAO4: выход 1 — мотор, выход 2 — направление (идёт на вход Z/F драйвера),
0 — открывать, 1 — закрывать. Концевики — герконы на вход 1 («открыто») и вход 2
(«закрыто»). Входы в режиме «Выключатель с фиксацией», с локальными действиями:

| Событие | Вход 1 «открыто» | Вход 2 «закрыто» |
|---|---|---|
| геркон замкнулся | выход 2 → включить | выход 2 → выключить |
| геркон разомкнулся | выход 1 → выключить | выход 1 → выключить |

Ворота наезжают на магнит, мотор разворачивается, ворота отскакивают назад, сходят с
магнита — и мотор гаснет. Ворота стоят у края магнита с направлением на обратный ход,
поэтому **чтобы двинуть ворота, достаточно включить выход 1**. Останавливает модуль сам,
даже если правило не работает.

## Установка

```bash
scp shluses.js add-dashboards.py root@192.168.хх.хх:/root/
ssh root@192.168.хх.хх 'cp /root/shluses.js /etc/wb-rules/ && python3 /root/add-dashboards.py'
```

`add-dashboards.py` дописывает в веб-интерфейс панели «Шлюз» (для пользователя, она же
панель по умолчанию) и «Шлюз — наладка». Бэкап конфига — в `/root/`, чужие панели не
трогает, повторный запуск заменяет свои.

После старта правила (и после каждой перезагрузки контроллера) положение ворот неизвестно,
поэтому обе ворота сначала едут закрываться. Уже закрытые наезжают на магнит, отскакивают
и встают — 1–2 секунды.

## MQTT

Прочитать — `/devices/<устройство>/controls/<контрол>`, команда — тот же топик с `/on`.

### `shluz` — для пользователя и внешней системы

| Контрол | Доступ | Назначение |
|---|---|---|
| `open_upstream` | кнопка | открыть верхний бьеф: закрыть ворота → налить камеру → открыть верхние |
| `open_downstream` | кнопка | открыть нижний бьеф: закрыть ворота → слить камеру → открыть нижние |
| `close_gates` | кнопка | закрыть обе ворота |
| `stop` | кнопка | остановить всё: моторы, клапаны, цикл |
| `reset` | кнопка | сбросить ошибку (ворота не двигает) |
| `init` | кнопка | инициализация: забыть положение ворот, сбросить ошибки, закрыть обе ворота до концевика |
| `status` | чт. | `init` — инициализация, `busy` — идёт цикл, `closed`, `upstream_open`, `downstream_open`, `unknown`, `error` |
| `step` | чт. | что сейчас делает (коды ниже) |
| `error` | чт. | причина ошибки, текст латиницей, например `upper gate: no limit switch within 30 s` |
| `upper_gate`, `lower_gate` | чт. | `closed` / `open` / `opening` / `closing` / `stopped` / `unknown` / `error` |
| `upper_pos`, `lower_pos` | чт. | насколько открыты ворота, %: 0 — закрыты, 100 — открыты, −1 — неизвестно (до первого концевика) |
| `level_mm` | чт. | уровень в камере, мм |
| `chamber_pct` | чт. | заполнение камеры, %: 0 — 70 мм, 100 — 140 мм (шкала задаётся на панели наладки), −1 — нет датчика |
| `chamber` | чт. | `full` — залита, `empty` — слита, `between` — между, `no_sensor` — нет показаний датчика |

Налив и слив идут до порогов уровня «залито» / «слито», заданных на панели наладки; не дошли
за отведённое время — клапан закрывается, ошибка, ворота не открываются.

Положение ворот (`upper_pos`, `lower_pos`) считается по импульсам мотора: на концевике 0 или
100 %, между концевиками — доля полного хода. В `step` процент обновляется каждую секунду.

Коды `step`:

| Код | Что делает |
|---|---|
| `closing_upper N%`, `closing_lower N%` | закрывает ворота (обе сразу — через пробел); при инициализации то же, `status` = `init` |
| `filling N%` / `draining N%` | наливает / сливает камеру через клапан, N — заполнение камеры |
| `crack_upper N%` / `crack_lower N%` | через клапан не идёт — приоткрывает верхние / нижние ворота |
| `filling_through_gate N%` / `draining_through_gate N%` | наливает / сливает через приоткрытые ворота |
| `opening_upper N%` / `opening_lower N%` | открывает верхние / нижние ворота |
| `opening_upper N%`, `closing_lower N%` и т.п. без цикла | ворота едут от ручной кнопки или внешней команды |
| `stopped` | остановлено кнопкой «Стоп» |
| `interrupted_manual` | цикл прерван ручной командой с панели наладки |
| `on_battery` / `ethernet_lost` | сбой: закрывает ворота |
| пусто | ничего не делает |

Новая команда посреди цикла прерывает его и начинает свою. При ошибке команды не
принимаются, пока её не сбросят.

### Примеры

`192.168.хх.хх` — адрес контроллера шлюза. Брокер Wiren Board по умолчанию пускает без пароля,
команды можно слать с любой машины в той же сети.

Смотреть всё, что отдаёт шлюз:

```bash
mosquitto_sub -h 192.168.хх.хх -v -t '/devices/shluz/controls/+'
```

Только состояние и шаг:

```bash
mosquitto_sub -h 192.168.хх.хх -v -t /devices/shluz/controls/status -t /devices/shluz/controls/step
```

Прочитать текущее состояние один раз:

```bash
mosquitto_sub -h 192.168.хх.хх -C 1 -t /devices/shluz/controls/status
```

Команды:

```bash
mosquitto_pub -h 192.168.хх.хх -t /devices/shluz/controls/open_upstream/on   -m 1
mosquitto_pub -h 192.168.хх.хх -t /devices/shluz/controls/open_downstream/on -m 1
mosquitto_pub -h 192.168.хх.хх -t /devices/shluz/controls/close_gates/on     -m 1
mosquitto_pub -h 192.168.хх.хх -t /devices/shluz/controls/stop/on            -m 1
mosquitto_pub -h 192.168.хх.хх -t /devices/shluz/controls/reset/on           -m 1
mosquitto_pub -h 192.168.хх.хх -t /devices/shluz/controls/init/on            -m 1
```

Как выглядит цикл «закрыть ворота» в подписке на `status` и `step` (ворота уже закрыты):

```
/devices/shluz/controls/status closed
/devices/shluz/controls/step closing
/devices/shluz/controls/status busy
/devices/shluz/controls/step
/devices/shluz/controls/status closed
```

Дождаться конца цикла в скрипте:

```bash
H=192.168.хх.хх
mosquitto_pub -h $H -t /devices/shluz/controls/open_upstream/on -m 1
sleep 2
until s=$(mosquitto_sub -h $H -C 1 -t /devices/shluz/controls/status); [ "$s" != busy ]; do sleep 2; done
echo "готово: $s"     # upstream_open — успех, error — смотреть /devices/shluz/controls/error
```

## Настройки

Настройки — пороги уровня, таймауты, калибровка датчика, реле заливочных насосов, ручное
управление воротами и клапанами — только в веб-интерфейсе контроллера, панель «Шлюз — наладка».
В API они не входят: внешняя система работает только с устройством `shluz`.

Клапан с заливочным насосом может питаться через реле на другом контроллере, включённое
последовательно с реле шлюза; правило включает его само вместе со своим. На время слива
выключается наполнение русла, чтобы потоки не мешали друг другу.

## Защиты

- **Блокировка** — кто бы ни включил мотор (правило, кнопка в веб-интерфейсе, внешняя
  система): ворота, поехавшие на открытие, останавливаются, если другие не подтверждены
  закрытыми или открыт любой клапан. Отскок от магнита блокировкой не считается.
- **Клапаны** — открываются только при закрытых обоих воротах; ворота перестали быть
  закрытыми — клапаны закрываются.
- **Таймаут хода** — не доехали до концевика — стоп и ошибка.
- **Ток мотора** — если задан порог и MAI6 отдаёт ток. Нет MAI6 — защита молчит.
- **Сбой питания или сети** — работа от батареи или пропал Ethernet: клапаны и обе
  ворота закрываются.

## Не проверено

- Пороги уровня и калибровка датчика по умолчанию — не мерились, на каждом шлюзе задаются на
  панели наладки.
- Реакция на пропажу Ethernet и на работу от батареи живьём не проверялась.
